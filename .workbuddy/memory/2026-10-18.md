# 2026-10-18

## 软件维度：nginx / 7-Zip / ZooKeeper / K8s 等应用与基础设施软件（同日追加）

用户要求「查询漏洞和软件健康度除了普通的依赖软件，新增软件漏洞类型，如 nginx,
7zip, zookeeper, k8s 等」。实现「软件维度」，与库维度（purl 生态）平行。

### 数据源选型（6 轮探测结论）

- **NVD CVE API 2.0**：`cpeName` 参数**不支持通配符**（`*` → 404），
  `virtualMatchString` 只查「所有版本受影响」的 CVE（nginx 41 条，不全）。
  **正解：`keywordSearch=<产品名>&resultsPerPage=2000` 一次拉全 + 本地 CPE
  `vendor:product` 前缀过滤**（nginx 447 条 → 精确命中 33 个 CVE）。
- **CPE vendor 坑**：nginx 的 CPE vendor 已是 **`f5`**（F5 收购迁移，
  `cpe:2.3:a:nginx:nginx` 查不到）；MySQL 要 `oracle:mysql` + `mysql:mysql`
  双前缀（8909 + 1175 个 CPE match）；Redis 要 `redis:redis` + `redislabs:redis`。
- **GitHub 健康度**：本机无 token 时 60 次/小时，先跑 12 个核心软件；
  全量 69 个由 CI 跑（默认 GITHUB_TOKEN 5000/h）。NVD 无 key 限流
  5 次/30 秒（脚本内置 6.5s 间隔，全量约 8 分钟），仓库可配 NVD_API_KEY 提速。
- GitHub release tag 形态五花八门：`v1.24.0` / `release-1.24.0` /
  `openssl-4.0.3` / `docker-v29.9.1` / `curl-8_23_0`——parse_release_version
  用 `^[A-Za-z][\w.]*?[-_]v?` 去项目名前缀 + `_`→`.`；zookeeper/mysql/postgres
  基本不建 GitHub Release，版本留空（前端显示未知）。

### 实现

- 新脚本 `scabase-fetcher/scripts/fetch_software.py`（~600 行，零三方依赖
  除 requests）：`SOFTWARE` 清单 69 个（name/aliases/keywords/cpe/repo），
  纯函数 `version_affected`（NVD CPE 区间判断，前端有对应 JS 实现）、
  `cpe_vendor_product`、`cve_touches_software`、`best_cvss`、`cve_record`
  （描述截断 300 字符 / 参考限 5 条 / 区间去重）；`--only` 刷新时**未选中的
  软件沿用旧数据**（否则产物会丢条目，为此专门修过 build_document）。
- 产物：`data/software-vulns.json`（1.9MB，12 软件 2253 CVE）+
  `data/software-support.json`（结构与 community-support.json 对齐，
  purl 用 `pkg:generic/<name>@<ver>`，前端复用 renderHealthCard）。
- 前端：输入 `nginx 1.24.0` / `nginx@1.24.0` / `k8s` / `7zip` 即走软件维度
  （别名最长匹配，与库输入可混合——软件行剥离后其余走原流程）；
  漏洞结果渲染到 `#softwareResults`（CVE 链接 NVD 详情、严重级徽章、
  版本区间文本），健康度到 `#softwareHealth`；chips 只列已采集到 CVE 的软件。
- CI：`.github/workflows/software-collect.yml`（每日 03:43 UTC，
  dispatch 支持 --only），提交回 data/；pages.yml 拷贝两个新文件
  （data/** 已覆盖）；Dockerfile 全目录 COPY 自动覆盖。
- 文档/索引：docs/oss-intake.md 第 18 节；llms.txt 加软件维度取数步骤；
  gen_data_index.py 加 2 个数据集（共 8 个）；readme 能力清单加一条。
